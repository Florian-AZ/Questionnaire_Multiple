# ADR 000002 — SQLite local et MySQL configurable

## Statut

Accepté, amendé le 10 septembre 2026. MySQL reste pris en charge ; SQLite devient le mode local par défaut.

## Contexte

Le projet utilisait une URL MySQL codée dans le back et un export SQL incomplet. Le démarrage dépendait d'un service MySQL configuré à l'identique sur chaque ordinateur. Il faut pouvoir tester le site immédiatement tout en laissant l'import de la base MySQL à l'utilisateur.

## Décision

Nous utilisons **SQLAlchemy** avec deux configurations :

| Mode | Activation | Initialisation |
| --- | --- | --- |
| SQLite | Aucune variable `DATABASE_URL` configurée | Création de `quiz.db` et des tables au démarrage |
| MySQL avec PyMySQL | `DATABASE_URL` définie dans `.env` ou l'environnement | Import SQL effectué manuellement |

Le fichier `.env` est recherché dans le dossier contenant `main.py`. Une variable déjà définie dans l'environnement du processus a priorité sur le fichier. Les paramètres de connexion restent séparés du code ; `.env.example` fournit un exemple et `.env` est ignoré par Git.

Au démarrage SQLite, les trois quiz de `Backend/seed.json` sont ajoutés si la table des questionnaires est vide. Un redémarrage avec des quiz existants ne les ajoute pas de nouveau.

Pour MySQL, l'utilisateur importe `BaseDeDonnée/questionaire.sql`, puis éventuellement `donnees_demo.sql`. Aucun appel automatique de création de tables ni d'import de démonstration n'est effectué en mode MySQL.

## Modèle conservé

| Table | Contenu |
| --- | --- |
| `utilisateurs` | Identifiant et pseudo de l'auteur ou du participant |
| `questionaires` | Titre, univers, auteur et moyenne |
| `questions` | Énoncé et questionnaire associé via `ID_Questio` |
| `reponse` | Proposition, question associée et indicateur `Vrai`/`Faux` |
| `participations` | Utilisateur, questionnaire et score en pourcentage |

Les noms historiques sont conservés pour correspondre aux modèles du projet. Le script MySQL utilise InnoDB, des clés étrangères et `utf8mb4`. Les clés étrangères sont également activées pour SQLite.

## Justification et alternatives

**MySQL seul** conserve l'environnement du cours mais impose sa configuration avant le premier test. **SQLite seul** simplifie le lancement mais ne répond pas au besoin d'importer une base MySQL. La configuration sélectionnable permet les deux usages avec les mêmes routes métier.

Une migration automatique des anciennes bases n'est pas ajoutée : le schéma est fourni pour un import manuel, conformément au fonctionnement demandé.

## Conséquences

- Les créations et participations persistent dans le moteur sélectionné.
- Les données SQLite et MySQL ne sont ni synchronisées ni transférées automatiquement.
- `CREATE TABLE IF NOT EXISTS` crée les tables absentes mais ne met pas à jour une ancienne structure.
- Chaque import du fichier de démonstration MySQL ajoute trois quiz supplémentaires.
- Si MySQL est configuré mais indisponible, l'API renvoie une erreur explicite ; elle ne bascule pas silencieusement vers SQLite.
- Le port de MySQL et celui du site sont distincts.
- La connexion doit être retestée après chaque changement de configuration et redémarrage du serveur.
