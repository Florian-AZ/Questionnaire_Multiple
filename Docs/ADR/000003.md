# ADR 000003 — Interface HTML, CSS et JavaScript connectée à l'API

## Statut

Accepté, mis à jour le 10 septembre 2026.

## Contexte

Le projet disposait de pages statiques, de quiz intégrés au HTML et de boutons de création sans enregistrement réel. L'interface doit maintenant afficher les données du back, publier des questionnaires et présenter les corrections renvoyées par le serveur, tout en restant simple à exécuter localement.

## Décision

Nous conservons **HTML, CSS et JavaScript sans framework frontend ni étape de compilation**.

L'interface repose sur trois fichiers principaux :

- `frontend/index.html` : structure commune, navigation et pied de page.
- `frontend/css/app.css` : styles, illustrations en CSS et adaptation aux tailles d'écran.
- `frontend/script/app.js` : rendu des vues, interactions, appels API et stockage du brouillon.

Les adresses `/`, `/catalogue`, `/creer` et `/jouer` servent le même fichier HTML. Le JavaScript sélectionne la vue d'après l'adresse. Les liens déclenchent une navigation normale ; chaque adresse peut aussi être ouverte directement.

## Comportement retenu

- **Accueil** : compteurs issus de la base et aperçu des quiz.
- **Catalogue** : recherche sans accents, filtres par univers et tri par récence, popularité ou longueur.
- **Création** : titre, univers, pseudo et éditeur de questions ; validation avant publication.
- **Partie** : réponses mélangées en conservant leurs identifiants, navigation entre les questions, puis correction serveur.
- **Résultats** : pourcentage de bonnes réponses, détail des corrections et confirmation de l'enregistrement.

Les appels `fetch` utilisent des chemins relatifs sous `/api`. Les informations issues des utilisateurs sont échappées avant leur insertion dans le HTML. Les erreurs du serveur sont présentées dans l'interface avec une possibilité de réessayer.

Le brouillon et le dernier pseudo sont conservés avec `localStorage`. Le brouillon est supprimé du navigateur après une publication réussie. Les choix d'une partie restent en mémoire jusqu'à la soumission ou au rechargement de la page.

## Choix visuels et accessibilité

L'interface utilise un fond clair, des tons verts, des cartes illustrées et une hiérarchie de titres commune. Elle s'adapte aux petits écrans, dispose de libellés de formulaire, d'états de sélection visibles, d'indicateurs de focus et d'un lien d'accès au contenu. Les animations tiennent compte de la préférence de réduction des mouvements.

Les fichiers nécessaires à l'affichage sont servis localement. Aucun service de polices ou d'images distant n'est nécessaire au fonctionnement du site.

## Alternatives considérées

- **React ou un autre framework** : utile pour un périmètre plus important, mais ajouterait un environnement de compilation inutile ici.
- **Pages avec données fixes** : insuffisantes pour refléter les créations et résultats de la base.
- **Serveur Live Server séparé** : non retenu ; le serveur de l'application fournit déjà les pages et l'API, comme décrit dans [l'ADR 000005](000005.md).

## Conséquences

Le démarrage reste limité à l'environnement Python. JavaScript doit être activé dans le navigateur.

Le brouillon appartient au navigateur et à l'origine utilisée : passer de `127.0.0.1:8000` à `127.0.0.1:8001`, ou de `127.0.0.1` à `localhost`, utilise un autre stockage. Effacer les données du navigateur peut supprimer ce brouillon. Les quiz publiés restent dans la base indépendamment de ce stockage.

Les anciennes pages redirigent vers l'application actuelle. La maintenance des vues reste manuelle dans le JavaScript ; aucune modification ou suppression des quiz publiés n'est exposée dans cette version.
