# ADR 000001 — Choix de FastAPI

## Statut

Accepté

## Contexte

Pour notre projet de questionnaire à choix multiples (QCM), nous avons besoin d'un backend permettant de gérer les questionnaires, les questions et les réponses.

Nous devons donc choisir une technologie adaptée au développement de notre API.

## Décision

Nous avons choisi d'utiliser **FastAPI** pour développer le backend et l'API REST de notre projet.

## Pourquoi ce choix ?

Nous avons choisi FastAPI pour plusieurs raisons :

- il est simple à utiliser et à prendre en main ;
- il fonctionne avec **Python**, que nous utilisons dans le projet ;
- il permet de créer facilement des API REST ;
- il génère automatiquement une documentation interactive avec **Swagger / OpenAPI**, accessible notamment via `/docs` ;
- nous avons étudié FastAPI en cours, ce qui nous permet de mettre en pratique les connaissances acquises et de mieux comprendre son fonctionnement.

## Alternatives envisagées

Nous avons envisagé plusieurs alternatives :

### Flask

Flask permet également de développer des API avec Python. Cependant, nous avons choisi FastAPI car il propose notamment une documentation automatique et une approche adaptée à la création d'API REST.

### Django

Django est un framework Python complet qui aurait également pu être utilisé. Cependant, ses nombreuses fonctionnalités ne sont pas nécessaires pour notre projet de questionnaire, qui reste relativement simple.

## Conséquences

### Conséquences positives

- Le backend sera développé en Python.
- Les différentes fonctionnalités du questionnaire seront accessibles via des routes API.
- La documentation de l'API sera automatiquement disponible avec `/docs`.
- L'équipe pourra tester facilement les différentes routes de l'API.
- Le projet nous permettra de mettre en pratique les connaissances acquises en cours.

### Conséquences négatives

- Les membres du groupe doivent comprendre le fonctionnement de FastAPI.
- Le choix de FastAPI nous rend dépendants de son écosystème pour la partie backend.

## Conclusion

FastAPI a été retenu car il est adapté aux besoins de notre projet, permet de développer rapidement une API REST et fournit automatiquement une documentation interactive. Ce choix nous permet également de mettre en pratique les notions étudiées en cours.
